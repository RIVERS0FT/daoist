# 外卖修仙 v0.8：地图手势与修仙基础

地图现支持光标锚点缩放、单指平移、双指捏合、触控板滚动偏好和键盘/四向按钮，视角菜单可显示全图或整单路线。手动浏览暂停跟随，“定位玩家”恢复跟随。配送点仍仅随当前任务出现。

修炼面板分为修行、功法、破境、药符。四门主修功法各有熟练度，法力与突破灵气分开；突破支持准备预览、稳妥/强行方案、可选护脉符与失败经验。炼气九层可进行三段内景试炼，完成后开放筑基初期。详细可验证成本见 `docs/CULTIVATION.md`。没有加入实时战斗、主动移动、宗门经营或现实时间挂机。

v1–v4 旧档自动升级为 v5；首次升级独立槽时原件保存在 `backup:pre-v5:<id>`，原 legacy autosave 仍保留。无需清档，不能在旧客户端继续写入 v5。AI relay 的 realmLevel 白名单已扩为 10；自行部署的旧 relay 需同步升级，否则筑基请求会明确回退为人工剧情。CI 使用模拟模型，无付费服务调用。

## 历史更新：v0.6 地图

城市画布扩大为 2400×1600；配送扩充为 24 个取餐点、40 个送达点。取送图钉只随当前订单出现，完成或取消后消失。地图保留生活/人物/修行等功能地标，并用“你在这里”显示玩家位置。

配送成功（骑行或推车）后角色停留在该订单目的地，位置随每个存档自动保存；刷新或切回存档可继续。接单、取消、骑行受阻或浏览地图不会移动玩家。右上角可定位玩家或当前终点。地图线段为示意，配送成本仍按本地引擎结算。旧存档不清档，无位置记录时从驿站补齐。

## 历史更新：v0.5 车辆与存档

开始页支持多个独立存档，经典 / AI 生成式剧情只在新建时选择，局内不可更改。每次行动自动保存，无需手动保存；可返回开始页继续其他仙途。旧 v1/v2/v3 单槽自动兼容升级并保留原件备份，不清空进度。

电动车没电、损坏或不足以完成全单时禁止骑行。跑单面板新增速度、电池容量、耐用性、节能四项升级及换电 / 维修；推车是明确的高耗时体力补救选项。存档仅保存在本机当前浏览器，清理网站数据会丢失本机进度。

## Daoist-Delivery / 外卖修仙

白天送外卖，晚上修仙。围绕时间取舍、NPC 关系与多结局的单机 Web RPG。

## 两种游玩方式

**经典剧情（默认）**：人工随机事件、NPC 分支与全部既有结局，不发送 AI 请求。正常跑单、修炼、生活、联系熟人，或点击“探索经典奇遇”。

**AI 生成剧情**：保留上述所有玩法；选择自由奇遇方向、可选熟人和虚构行动意图，由模型生成新场景及 2–4 个选择。本地规则显示并结算时间、资源和关系影响。最近的奇遇形成短期记忆，支持继续生成。

两个模式只在新建存档时选择，每个存档独立保存模式和进度，局内不可切换。每次探索先花 15 分钟和 2 精力，选择另计时间；失败回退不重复收费。已有 AI 场景存入本机，刷新不重抽，也可以断网后在当前模式下完成该段。AI 不直接修改主线旗标、人物路线、境界或结局。

## 开始玩

线上：https://rivers0ft.github.io/Daoist-Delivery/

开始页点击“新建存档”，选择经典剧情或 AI 生成式剧情；已有存档从列表继续。局内左下角“奇遇”与“更多 → 设置”只显示本存档的固定模式。AI 模式需要在“AI 服务设置”保存 relay 地址、授权及可选访问口令；没有服务或生成失败会明确回退为人工剧情，不伪装成 AI 已连接。接入步骤见 [server/README.md](server/README.md)。仓库提供可运行 relay，GitHub Pages 本身不运行模型服务。

不要在前端填写模型供应商 API Key。模型密钥只在服务端；relay 访问口令仅存在当前页面内存，刷新后重新输入。真实模型调用可能收费，未配置服务时经典玩法不受影响。

## 已有内容

连续游戏时间、四类天气、配送与高峰收益、电量、钱/精力/健康/压力/信誉/房租、夜修、炼气一至九层与筑基初期、原有 60+ 人工事件、5 名核心 NPC、多维关系与多条友情/情感/同道/伙伴/家人/疏远路线、第 30 天后的多结局。新增 6 个人工自由奇遇作为经典玩法和 AI 回退。

IndexedDB 使用独立存档槽和 v5 会话封装，兼容 v1/v2/v3/v4 老存档，不需要重新开局。保存最近 12 段奇遇；未知未来存档不会自动覆盖。桌面和手机均可操作。

## 开发与测试

```bash
npm install
npm run dev
npm test
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

AI relay：复制 `server/.env.example` 为 `server/.env.local`，在服务端配置后运行 `npm run relay`。前端也支持 `.env.local` 的公开 `VITE_NARRATIVE_AI_ENDPOINT` 默认地址，但仍须玩家选择生成模式并同意外发虚构上下文。

CI 使用模拟模型，不使用或消耗生产密钥。真实供应商接入需用实际服务另行验证。规则见 `AGENTS.md`、`docs/GAME_DESIGN.md`、`docs/ARCHITECTURE.md` 和 `docs/PLAY_MODES.md`。

## 地图主界面

从开始页创建或继续存档后进入青岚市地图。顶部查看时间、天气与资源，左下角使用地图 / 跑单 / 修炼 / 人物 / 奇遇 / 更多导航；生活、状态、见闻、结局与设置在“更多”中。点击地点只打开功能，不消耗时间。地图可拖动、缩放，也可通过地点列表访问常驻功能地标；配送任务点不在常驻列表中。待处理故事可关闭后再从“继续处理”打开。手机面板独立滚动，顶部和左下导航保持可见。

地图为游戏内虚构区域，取送虚线为示意；地图浏览不影响存档进度、人物路线或游戏时间。详见 `docs/MAP_INTERFACE.md`。
