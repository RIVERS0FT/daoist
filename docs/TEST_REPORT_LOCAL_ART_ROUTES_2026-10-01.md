# 本地美术资源路由与空白页修复

日期：2026-10-01。应用 1.22.0，存档 v25；仅本机修复与验证，未提交、推送或部署。

## 原因与修复

真实 `http://127.0.0.1:8787/` 首页返回 200，但固定静态白名单遗漏新 `js/art.js` 和 16 张美术 PNG，资源返回 404。浏览器拒绝执行 JSON 类型的 404 响应，`app.js` 初次渲染读取缺失的 `G.Art.application` 时抛出 TypeError，开始页内容为空。上一轮离线静态文件路由验证没有覆盖实际应用服务器。

`server.mjs` 增加 `art` 脚本与固定 16 张正式 PNG 路由；不开放目录遍历或任意文件。保持原 MIME、CSP、`no-store`、`nosniff` 与私有文件隔离。已确认监听端口的原进程启动命令为 `node --env-file-if-exists=.env server.mjs`，只重启该游戏服务，保留相同工作目录、端口与启动参数。

## 验证

- 服务器 Node 专项 **49 / 49 通过**。新增测试解析真实 `index.html`，逐一 HTTP 获取全部 21 个脚本、2 个样式和 favicon，验证状态、MIME、缓存头及源码字节；全部 16 张 PNG 检查签名、长度与字节。未知美术路径、越界路径、环境文件和服务端文件仍为 404。
- `node --check server.mjs` 和 `git diff --check` 通过。
- 重启后真实 8787 请求：首页、`js/art.js`、应用图标、主视觉均返回 200；脚本为 `text/javascript`，图片为 `image/png`。
- Edge 154.0.4258.48（Chromium，headless）直接访问真实 8787 服务，1440×1000 和 375×812 两视口均通过：开始页全部图像正常加载、新建角色成功、暂停 / 帮助 / 座驾可用，没有页面异常、失败请求或 HTTP 错误，没有页面横向溢出。

诊断与截图保存在忽略目录 `artifacts/local-blank-diagnosis/`。服务器测试的 AI 上游为测试替身；实际页面验收使用本机服务，不拦截网络请求或模拟响应。测试浏览器使用独立上下文，不修改用户浏览器存档。
