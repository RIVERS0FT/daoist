## 实际帧长与模块耗时

执行构建版专项：

```text
browser-performance.py --root dist --scenes pan,zoom,travel,panel,region-load,region-detail --output artifacts/performance-chapters
```

测试为 headless、CPU rate 1；每个视口六个场景，共十二个，全部通过现有预算（P95 ≤ 33.5 ms、最大帧长 ≤ 150 ms、超预算比例 ≤ 10%）。

| 场景 | 桌面 P95 / 最大 ms | 手机视口 P95 / 最大 ms |
| --- | ---: | ---: |
| 拖动 | 8.280 / 22.414 | 6.848 / 10.784 |
| 缩放 | 16.657 / 28.875 | 7.478 / 13.050 |
| 移动 | 6.294 / 24.205 | 6.614 / 51.815 |
| 面板 | 7.386 / 83.837 | 7.022 / 89.916 |
| 全市分区加载 | 18.493 / 145.410 | 14.585 / 21.125 |
| 外围街巷细节 | 6.993 / 11.718 | 7.530 / 131.155 |

- 每帧包含全部 20 个加载脚本模块的采样自耗时，包含新增 `chapters.js`，另列布局、绘制、合成、栅格线程和 GPU 服务线程开销。
- 区域场景先开放十二章，测量真实背景加载和绘制，不以锁区遮罩冒充全图性能。
- 测量自检注入 200 ms 阻塞，观察到 203.079 ms，并正确识别超预算。
- 最重场景超预算比例 8.276%；加载仍存在约 145 ms 单帧尖峰，不能据此声称始终稳定 60 FPS。
- RAF 回调入口间隔不是物理屏幕呈现帧长；V8 采样的零值仅表示未采到，GPU 服务线程 CPU 时间不是精确 GPU 执行时间。真机、可见窗口和用户设备仍可能不同。

逐帧 JSON、全部模块归因、CPU profile 与 trace 保存在 `artifacts/performance-chapters/`。本次没有重复与此修改无关的完整功能套件。
