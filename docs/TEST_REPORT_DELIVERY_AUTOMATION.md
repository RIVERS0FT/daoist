# 自动交付与浏览器并行验证（2026-09-28）

应用仍为 1.21.0，未修改玩法、public 资源或存档 schema。本报告记录功能分支 `ci/automated-delivery` 的本机验证，不代表 GitHub 工作流已经上线。

## 修改

- PR 完整严格验证后保存包含 head/base/tree 与 run/attempt 的构件证据。
- `release.yml` 通过工作流完成事件接续明确登记到 head SHA 的发布请求；检查通过后 squash merge、复用构件、发布与逐文件公网校验。
- 本机 `ship` CLI 执行提交/推送/PR/登记请求；等待交给普通进程，每分钟查询一次，结束输出结果。失败摘要、完整日志及结构化结果保留在 runner，并回写 Actions 与 PR。
- 浏览器原 257 项检查拆成 21 个独立场景组，两个进程隔离执行；性能采样仍然串行，原真实时钟、后台定时器、AI 迟到响应等时间断言未缩减。

专项测试通过本地封闭 GitHub transport 执行真实发布控制器；不会发起公网合并、PR 评论或部署。覆盖：

- 成功路径恢复已测字节、带精确 head 合并、返回成功结果。
- 未登记请求的普通 PR 无合并、部署或评论副作用。
- PR 新提交、不同仓库/工作流、草稿、基线变化、构件损坏、错误 run/attempt、过期、目录重定向被拒绝。
- 合并后内容树变化记录合并结果，但不发布。
- CI 失败提取相关错误日志、脱敏并停止合并。
- 发布请求成功完成后，重复事件不再合并或上传。
- 上传结果未知时停止盲目重试；上传成功而公网校验失败时仅重验，不重复上传。
- 日志包装器保留 stdout/stderr、失败退出码和耗时。

Windows 受限沙箱最初阻止 Node / Playwright 创建子进程（`spawn EPERM` / `WinError 5`）；上述通过结果来自允许创建子进程的本机执行环境。

## 验证边界

- 349.793 秒是本机并行浏览器结果，不可直接与此前服务器 16 分 07 秒比较或据此声称服务器加速比例；服务端需用新工作流实测。
- 尚未执行新工作流的真实 GitHub 自动合并、production 密钥发布或公网验收。控制器必须先进入 main，之后才接收 `workflow_run`；功能分支中的工作流不会自行安装。
- 本次未改变运行时和性能预算，也未重新声明现有桌面帧预算问题已修复。所有自动交付必须严格 CI 成功，上次单次发布豁免不会继承。
- 不同 main 基线或过期构件返回重新验证的错误，不自动重写用户分支。runner 离线时事件会排队；客户端超时只停止本地等待，不将远端运行误报为已取消。
- 仓库负责 Actions / PR / CLI 结果；已结束的聊天会话自动通知需要额外客户端集成。
