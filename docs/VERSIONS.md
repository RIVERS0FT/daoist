# 版本记录

本文件是应用版本变化的唯一长期记录。当前应用版本为 **1.19.0**，当前存档 schema 为 **v22**。

版本历史记录“这一版改变了什么”；当前有效玩法写在 [GAME_DESIGN.md](GAME_DESIGN.md)，当前技术实现与不可破坏的工程边界写在 [ARCHITECTURE.md](ARCHITECTURE.md)，验证证据写在对应的 `TEST_REPORT*.md`。README 不再承载版本历史。

## 新版本记录规范

从**下一个新版本**开始，每个版本必须固定按以下三个方面记录，三个标题都不能省略。某一方面没有内容时写“无”，不要把修复或优化混到“新增”里。

```markdown
## x.y.z：版本标题（YYYY-MM-DD）

### 新增
- 新功能、新内容、新系统、新数据。

### 修复
- Bug、错误规则、兼容问题、回归问题。

### 优化
- 体验、性能、文案、结构、可维护性与非功能性改进。
```

版本号只在确实形成应用版本时递增。纯文档整理、CI/部署维护若不改变应用版本，可记录在架构或测试报告中，不虚增游戏版本。

## 1.18.0：十二章人物化扩写（2026-09-23）

本版继续扩充既有十二章，不增加第十三章，也不把主线改成新的分支树。目标是让“章节”不只承担境界和配送门槛，而能持续呈现主角、外卖系统器灵与已结识人物如何理解同一件事。应用版本升为1.18.0；存档结构仍为v21，存储键仍为`night-courier:saves:v21`，没有新增持久化字段、主线标记、奖励或经济渠道。

### 三层章节内容

第一层是`G.STORY_STAGES`与高境界章节的章节描述。十二章都补充了当前矛盾、人物立场与阶段性问题：第一章从“完成十单”落到普通骑手为什么仍愿意把饭送热；第二章强调得到力量后生活并未被跳过；第三章学习区分线索、历史与想象；第四章把修行圈写成有交班、疲惫和边界的具体人群；第五章拒绝把人压平成“阵点”；第六、七章分别处理系统的回避与真相；第八至十二章继续推进同意、旧连接、共同承担、经验传承与渡劫后的自主选择。

第二层是原有固定剧情正文。保留全部既有事件ID、章节门槛、三个选项、效果、成本、耗时和完成标记，只扩写正文与人物反应：首单、第一章第十单系统解锁、`story-street-vein`至`story-system-truth`五场前期主线，以及化神至渡劫十场高境界主线。器灵因此形成连续的人物弧线：从只会计算“有效连接”，到无法解释人的差异；从害怕连接减少、拒绝回答，到承认旧阵失败；再学习说明、等待同意、接受沉默与结束、分散责任、允许善意不被计数，最终不再给玩家唯一答案。它仍是固定主线角色，不交给AI改写。

第三层是只读的章节人物侧写`G.CHAPTER_CHARACTER_BEATS`。十二章各有一个章节问题和3–4条人物视角，共覆盖全部21位具名NPC；`G.chapterCharacterNotes(s, stageId)`只返回`bonds[id].met===true`的人物，并补姓名与职业用于显示。查询不推进时间、不抽随机数、不发奖励、不结识人物、不改变关系，也不会把章节侧写写进存档或AI上下文。外卖系统“委托”页在任务列表前展示当前章描述、章节问题和已结识人物的旁注；没有匹配人物时只显示提示，不列出隐藏姓名。

章节侧写用于强化人物既有性格而不是创造新能力。例如陈默以“人也得歇”理解第一章，程砚秋以“宁留缺口、不猜字”回应第三／九章，林晚从包办转向轮值回应第五／十章，江临用可解释和可维护的系统观回应第六／十一章。人物仍保留各自个人故事、职业边界、常约地点和关系路线；侧写不是个人剧情结算，不能推进`bonds.stage`。

### 剧透与人物边界

未结识人物绝不出现在章节侧写中。章节卡只展示当前章，不用全人物目录提前曝光后续角色。周野只在第一章侧写出现一次，内容严格停留在普通骑手、同行互助与跑单经验，不出现修仙、灵力、黑签、蚀灯会、组织、背叛或仇人等后期信息；其第六段／第七段实际结算后的分阶段身份规则继续由1.17.0约束。

委托奖励文字也同步修订，避免旁路剧透主线。旧q3在炼气阶段直接宣布系统是护城阵，早于第六、七章的“追问→真相”节奏；本版改为只描述看见异常、继续求证。q1–q8只补叙事与人物主题，不修改ID、完成单数、境界要求或奖励。已经结算的历史回执和日志仍按原保存内容保留；静态配置更新只影响之后展示／未结算的可信模板。

### 规则、兼容与验证

第一章仍要求先完成九单，再把第十份热饭送至非常驻随机地点并完成固定选择后解锁外卖系统；解锁单本身仍没有外卖币，第二章仍须领取q1才开放修行。第三至第十二章的境界、配送数、前章完成关系不变。宗门、周野十段线、21位NPC个人故事、女性感情线、丹方、炼药、拍卖、道路、电动车、房租优先、暂停／停止与结局均不改。

应用版本1.18.0只表示内容与只读界面扩充，存档继续v21；因此旧档无需迁移或重开，资产、关系、主线标记、进行中行动、票据、历史结果与日志都不补算、不重置。新增专项测试覆盖十二章／21人侧写完整性、未结识过滤、查询纯度、周野前期防剧透、固定主线ID与三选项稳定性以及未知章节边界。完整验证记录见`docs/TEST_REPORT_1.18.0.md`。

## 1.3.4：时间倍率选择框保持稳定（历史）

修复世界时间推进到订单刷新、昼夜/日期边界等需要完整界面刷新的节点时，顶部时间倍率选择框被重建、从而在操作中突然关闭的问题。顶部状态栏现在只在首次进入游戏时创建；后续世界刷新仅更新玩家信息、货币、天气、资源与时间文本，`#time-speed` 和整个 `.time-controls` 节点保持不变，因此正在聚焦或展开的原生选择框不会被刷新打断。

浏览器回归会把倍率设为 10 倍并聚焦选择框，推进到 15 分钟订单刷新边界，再断言选择框和时间控件容器仍是同一 DOM 节点、焦点仍在选择框且倍率仍为 10 倍。存档格式不变。

## 1.3.3：修复配送点进度环对齐

修复部分浏览器/缩放状态下配送点图标与圆形进度环错位的问题。进度环现在使用 SVG 自身的 `rotate(-90 0 0)`，明确以配送点局部坐标原点为旋转中心，不再依赖 CSS 的 `transform-origin:center`。浏览器测试新增点心与圆环中心坐标重合断言。

## 1.3.2：订单消失时间与地图进度环

配送订单不再有“送达时限”。地图上的未接订单只保留**消失时间**：到点前可以接单，接下后订单立即锁定，途中停止、改道、处理配送事件都不会因为耗时而失效，也不会因晚送降低现金、外卖币或口碑奖励。为兼容现有 v7 存档，订单内部仍沿用 `expiresAt` 字段名，但它现在只表示“未接订单从地图消失的游戏时间”。

地图配送点新增圆形剩余进度环，环形随游戏时间连续缩短；新订单出现时淡入弹出，订单自然消失、取消或配送完成后缩小淡出。动画只改变视觉，不参与规则判定；系统“减少动态效果”偏好下会自动跳过动画。普通地点和已接订单仍保持可点击，已接订单不显示消失倒计时。

本次不改变存档结构，继续使用 `schemaVersion: 7`。旧档中的待接订单按原 `expiresAt` 作为一次性的地图消失时间继续兼容；旧档已经接下的订单会忽略该时间。PR #10 完整 CI 已验证 `npm test` 183/183、Chromium 29/29，并通过语法检查与静态构建。
