# 整帧与模块耗时专项 · 2026-09-27

## 问题与修改

前一轮只比较地图函数的同步耗时，遗漏了浏览器在 JS 之后的栅格化和合成，不能证明帧率改善。本轮真实 RAF 探针在原 SVG 底图上复现连续缩放约 26 FPS、P95 约 206 ms；关闭模糊效果、阴影和动画不能消除卡顿，隐藏静态底图后帧率恢复。

静态底图改为从同一可信 SVG/路网几何生成 Canvas 瓦片。每块逻辑 192 px、双倍像素密度；新瓦片每帧绘制一块，沿路道路裁剪至瓦片范围，卸载缓存上限 48 MiB。旧内容保留到新内容完成，日夜和总览细节变化清理缓存。Leaflet 瓦片明确允许负缩放级别。地点、路线、玩家和结算仍使用原世界坐标与状态逻辑。

## 测量口径

新增 `tests/browser-performance.py`、`tests/frame_metrics.py`、预算配置及解析器边界测试。性能脚本直接运行源码或构建，使用真实 RAF、游戏时钟、存储、鼠标拖动和滚轮；不复用功能测试的受控时钟或逐帧状态克隆。

- 帧长：相邻 RAF 回调实际进入时间，另存 RAF 参数时间戳差。门槛检查 P95、最大帧长和超预算比例，同时报告 P50/P99、FPS 与超过 50 ms 的帧数。
- 模块：所有 15 个加载脚本逐帧列出 V8 500 μs 采样自耗时，包括地图、瓦片、引擎、时钟、存储、主线、宗门、数据与 app。内建调用归属最近源码父调用；零采样表示该场景未采到，不表示绝对零耗时或所有玩法分支均执行。
- 浏览器：同主线程的样式、布局、绘制、合成、总忙碌区间按并集统计；另列栅格工作线程和 GPU 服务线程。多线程有重叠，不能直接相加得到帧长，也不把 GPU 服务线程 CPU 时间称作 GPU 硬件执行时间。
- 200 ms 阻塞自检：在地图函数之外注入定时器阻塞，观察到最大帧长 **203.225 ms**，同时捕获 Long Task，确认会触发 150 ms 门槛。

阈值：目标帧预算 16.667 ms，P95 ≤ 33.5 ms，最大帧长 ≤ 150 ms，超过预算加 0.5 ms 的帧不超过 10%。失败退出非零；不通过删除慢帧、改动游戏倍率或关闭地图效果获得通过。

## 本地运行服务复核

用户反馈 `http://127.0.0.1:8787/` 地图空白。实测首页及 `map.js` 返回 200，但新增 `map-tiles.js` 返回 404：运行中的旧 Node 进程未加载已经修改的静态资源白名单。此前通过路由读取源码/构建的浏览器专项未覆盖这个仍在运行的旧服务。

重启该端口对应的项目服务后，直接通过真实 HTTP 地址验证，不拦截请求、不替换游戏时钟或存储。桌面 1440×1000 和手机 375×812 视口各自新建隔离浏览器会话，15 个脚本全部返回 200，页面脚本错误和失败请求均为零。开局以及缩放、拖动后均检查 Canvas 实际非透明像素和多种颜色，确认底图正常绘制。证据保存在 `artifacts/localhost-map-check.json` 与 `artifacts/localhost-map-1440.png`、`artifacts/localhost-map-375.png`。未操作用户浏览器资料或已有存档，未重跑完整套件。

## 交付边界

只运行本轮性能与地图相关专项，未运行完整 Node / 浏览器功能套件；完整测试留到推送前。PR CI 与 RIVERSOFT 验证已加入帧预算检查和报告归档，但未提交、推送或运行远端工作流。

实体手机、其他浏览器、用户当前设备的真实显示帧率尚未验收。RAF 回调间隔不是物理屏幕呈现时间，V8 数据是采样估计；源码初始化模块在持续交互场景中可能没有样本。面板首次打开仍可出现较长单帧（本机最大 136 ms），报告保留该尖峰，没有将其排除。
