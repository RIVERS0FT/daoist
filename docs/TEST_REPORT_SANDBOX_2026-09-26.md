# RIVERSOFT 沙箱开局回归（2026-09-26）

## 问题与修复

1.20.0 部署后，25 个公网文件与 CI 构建哈希一致，但实际点击新建角色触发 Chromium 的 `Blocked form submission`。公网 CSP 为 `sandbox allow-scripts allow-pointer-lock`，不允许原生表单提交；仅测试无沙箱页面不能覆盖这个问题。

1.20.1 将点击和名字输入框回车接到同一个创建入口，显式运行表单约束校验，再调用原有 `G.newGame`、存档和载入流程。输入法组合期间不处理回车。没有改动玩法、存档 schema 或托管平台的权限策略。

## 验证范围

- `tests/browser-smoke.py` 使用实际构建产物和匹配生产限制的 CSP 响应头，不注入模拟 localStorage 或 fetch。
- 空名字点击/回车均不创建，输入法组合回车不创建；有效点击创建经典模式，有效回车创建 AI 模式；每次仅创建一份角色，地图正常显示。
- 断言本地存储确实受到沙箱限制，并保留现有存储受限提示。
- 存储提示改为参与布局，回归覆盖 1440×1000、375×812、667×375，实际点击暂停和四个地图控件，检查无横向溢出。
- 完整检查执行结果以本次 PR 和 RIVERSOFT 工作流为准；公网再单独核对所有构建资源和三个视口的地图交互。

静态托管不提供真实 AI 代理和可靠 localStorage；本次修复只处理开局入口，完整本机运行仍使用 `npm start`。
